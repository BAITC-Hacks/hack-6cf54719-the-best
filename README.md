## PostgreSQL и роли

Сервер хранит пользователей, задачи, предложения и сессии в PostgreSQL.
Роли приложения (не отдельные пользователи PostgreSQL):

| Роль | Права |
| --- | --- |
| student | Просмотр задач и отправка предложений |
| business | Создание задач и просмотр предложений к своим задачам |
| admin | Создание задач, просмотр всех предложений, список пользователей и изменение ролей |

Каталог и детали задач доступны без входа. Самостоятельная регистрация разрешена
для student и business. Подтверждение принадлежности к компании пока не реализовано.
Роль admin через регистрацию получить нельзя.

### Запуск

1. Запустите Docker Desktop (Linux containers).
2. Создайте `.env` из `.env.example`, если файла ещё нет. Задайте
   `POSTGRES_PASSWORD` случайной строкой из букв и цифр (без пробелов и URL-символов).
3. Выполните `docker compose up -d --build`.
4. Откройте http://localhost:8000/docs.

PostgreSQL доступен по localhost:5432, база и пользователь — `ai_sana`.
Пароль находится в вашем `.env`. Данные сохраняются в Docker volume `postgres_data`.
`docker compose down` сохраняет данные; флаг `-v` удаляет том вместе с БД.
При запуске создаются отсутствующие таблицы. Изменение уже существующей схемы
потребует миграций: `create_all` не изменяет существующие столбцы.

### Первый администратор

Выполните `docker compose exec backend python -m backend.create_admin`.
Введите имя, email и пароль (от 10 символов); пароль вводится скрыто.
Команда не повышает роль уже существующего пользователя.

### Создание карточки представителем бизнеса

В `/docs`:
1. `POST /auth/register`: передайте email, name, password и `role: "business"`.
2. Нажмите **Authorize**: в username введите email, затем пароль.
3. Выполните `POST /tasks` с телом:

```json
{
  "title": "Автоматизировать сводку отзывов",
  "company": "Qazaq Market",
  "industry": "Ритейл",
  "summary": "Нужно выделять повторяющиеся проблемы из отзывов",
  "users": "Команда поддержки",
  "data": "CSV с отзывами",
  "deadline": "3 недели",
  "tags": ["python", "ai"]
}
```

Владелец берётся из текущей сессии, новая задача получает статус «Черновик»
и рейтинг 0. Клиент не может подставить чужой owner_id или повысить score.
`GET /tasks` и `GET /tasks/{id}` возвращают сохранённые карточки.
Студент отправляет предложение через `POST /tasks/{id}/proposals`.
Автор задачи читает предложения через `GET /tasks/{id}/proposals`.

Пароли хешируются Argon2. Токены действуют 12 часов; в БД хранится только их
SHA-256 хеш. Выход через `POST /auth/logout` отзывает текущий токен.
Права проверяются по актуальной роли пользователя при каждом запросе.

Существующие frontend/app.py и frontend/index.html пока используют демоданные.
Форма создания и вход доступны в API-документации; подключение пользовательского
интерфейса к API — отдельный следующий шаг.

### Проверка

На запущенной БД:

```sh
docker compose exec backend pip install -r backend/requirements-dev.txt
docker compose exec backend python -m unittest backend.test_api -v
```

Тесты проверяют регистрацию, вход, ограничения ролей, создание задач и откликов,
доступ к чужим откликам, выход и срок токена. Данные каждого теста откатываются.
